# 不需要打开经典蓝牙，选择NimBLE

## 文档目标

为鸿蒙逃生 App 提供室内周边定位（蓝牙信标）能力，本固件需在现 ESP32 应急灯/指示牌节点上新增 BLE 信标广播，使手机 App 能扫描到"当前所在节点"，再由云端完成节点 + 楼层判定。

本文档为固件侧开发规划与规范：明确要开发的功能、广播格式、开发步骤与验收方式。本阶段只输出文档，不修改现有固件源码。

## 现有固件工程现状（已核实）

| 工程 | 位置 | 技术栈 | 职责 |
|---|---|---|---|
| 主节点 master_node | New_version_of_emergency/master_node | ESP-IDF + C++ | LTE-MQTT 上云、LED 矩阵显示、Mesh 下播、传感采集 |
| 子节点 child_node | New_version_of_emergency/child_node | ESP-IDF + C++ | Mesh 组网、LED 方向显示、蜂鸣器 |
| 吸顶灯 | 遥顶灯源码/src/ce智慧顶灯 | ESP-IDF + C | 传感器采集并 MQTT 上报 |

关键结论：

主/子节点工程目前无任何蓝牙（BLE）实现代码（检索 esp_ble/BLEDevice/广告 等无结果）

sdkconfig.defaults 未启用蓝牙子系统（无 CONFIG_BT_*）

设备标识：ESP32_<MAC> 为节点身份（MQTT JSON key、下发控制均用 MAC）

无线通道现有：WiFi + ESP-NOW/Mesh + MQTT；蓝牙未被占用，可叠加

## 待开发功能（本期固件目标）

| 编号 | 功能 | 说明 |
|---|---|---|
| B1 | BLE Beacon 广播 | 每台节点持续广播 iBeacon，间隔 200ms~1s（可调） |
| B2 | 广播携带节点标识 | Beacon 的 Major=楼层、Minor=节点号，App 可解析出 node_id |
| B3 | 与现有功能共存 | 不干扰 WiFi / Mesh / MQTT / LED / 报警 |
| B4 | 可配置开关 | sdkconfig 或头文件可开启/关闭、调功率与间隔 |
| B5 | 与 App 对齐 | App 扫描可得 UUID / Major / Minor / RSSI |

**不需要实现：**经典蓝牙（BR/EDR）、BLE 连接/配对、数据通道。

## 广播报文设计（固件与 App 的协议约定）

推荐 iBeacon 格式：

| 字段 | 长度 | 内容 | 示例 |
|---|---|---|---|
| 厂商前缀 | 2B | 0x004C（Apple） | 4C 00 |
| iBeacon 类型 | 1B | 0x02 + length | 02 15 |
| UUID | 16B | 项目统一固定值 | E0C5E6D8-…（全楼宇相同） |
| Major | 2B | 楼层（1F=1…） | 0x0002 |
| Minor | 2B | 节点编号 | 0x0003 |
| TXPower | 1B | 参考 RSSI@1m | 0xC5（-59） |

楼层和节点编号直接写入到esp32的flash的nvs分区上，第一次烧录的时候写入，后面直接把代码注释掉即可，每个硬件都是不同的！！！写报文的时候直接从flash上读取。

备选：Eddystone-UID 或自定义厂商数据，需同步修改云端解码；推荐 iBeacon。

云端映射表（定位语义）：

| Major(楼层) | Minor(节点) | node_id | 平面坐标 | 设备 MAC |
|---|---|---|---|---|
| 1 | 1 | node_1f_01 | (x1,y1) | ESP32_D8:BC:… |
| 2 | 3 | node_2f_03 | (x3,y3) | ESP32_2F… |
| … | … | … | … | … |

## 开发步骤（master_node / child_node 通用）

### 启用蓝牙子系统（不启用经典蓝牙）

打开到 sdkconfig 增加：

这个使用上面的图片图形化即可，不用管，AI写代码忽略这个，不用去修改sdkconfig文件，图形化配置

![image_4.png](蓝牙开发文档_images/image_4.png)
![image_5.png](蓝牙开发文档_images/image_5.png)

```text
# BLE（低功耗蓝牙）
CONFIG_BT_ENABLED=y
CONFIG_BT_BLUEDROID_ENABLED=y
CONFIG_BT_BLUEDROID_CLASSIC_BT_DISABLED  # 不启用经典蓝牙
CONFIG_BT_NIMBLE_ENABLED=y               # 不推荐 Bluedroid 占用大的话选 NimBLE
```

建议：二选一（NimBLE 更省内存），本项目使用 NimBLE。

### 新增 beacon 组件

```text
master_node/components/BLE_Beacon/
├── CMakeLists.txt
├── ble_beacon.c
└── ble_beacon.h
```

接口骨架（ble_beacon.h）：

```text
typedef struct { int16_t major; int16_t minor; int8_t tx_power; } beacon_cfg_t;
esp_err_t ble_beacon_init(const beacon_cfg_t *cfg);   // 初始化 BLE（非阻塞）
esp_err_t ble_beacon_start(void);
esp_err_t ble_beacon_stop(void);
```

核心流程（ble_beacon.c，示意骨架）：

```text
// 1. 只保留 BLE，释放经典蓝牙内存
esp_bt_controller_mem_release(ESP_BT_MODE_BT_CLASSIC);
// 2. 初始化并使能控制器
esp_bt_controller_init(&bt_cfg);
esp_bt_controller_enable(ESP_BT_MODE_BLE);
// 3. （使用 Bluedroid 时）初始化并 enable
esp_bluedroid_init(); esp_bluedroid_enable();
// 4. 构建 30 字节：02 01 06 1A 4C 00 02 15 UUID… Major Minor TXPower
// 5. esp_ble_gap_config_adv_data(&advOrigin, &advData);
// 6. 设置 adv 模式（不可连接、广播间隔 200ms~1s）
// 7. esp_ble_gap_start_advertising(&advParams);
```

### 主程序接入

在 app_main() 初始化中加入：ble_beacon_init(&cfg); ble_beacon_start();

节点身份：复用现有 g_mac_str（ESP32_%s），将 MAC 尾字节映射为 Minor、楼层映射为 Major（mac-enum 映射表）

保持原有 WiFi/MQTT/LED 初始化顺序不变，beacon 最后启动

## 验证与验收

| # | 验证项 | 方法 | 通过标准 |
|---|---|---|---|
| 1 | Beacon 可见 | nRF Connect / 鸿蒙蓝牙扫描 | 看到 iBeacon 帧与项目 UUID |
| 2 | 信息正确 | 解析 Major/Minor | 楼层/节点号与云端映射一致 |
| 3 | 可测距 | App 看 RSSI | 1m≈-58±5dBm；5m 可识别 |
| 4 | 无干扰 | 同时走 MQTT/报警测试 | WiFi、LED 不中断 |
| 5 | 稳定性 | 连续 24h 运行 | 无重启、无泄漏 |

## 与鸿蒙 App / 云端衔接

App 扫描后上报：

```text
{
"deviceId": "uuid",
"beacons": [
{ "node_id": "ESP32_D8:BC:38:78:21:98", "rssi": -65 },
{ "node_id": "ESP32_2F_03", "rssi": -72 }
]
}
```

云端依据映射表+RSSI 执行基站/加权质心定位；固件与云端需维护同一份 iBeacon 映射表（建表、录坐标）。

## 风险与注意

| 风险 | 影响 | 应对 |
|---|---|---|
| WiFi/BLE 共存 | 偶发广播丢包 | 广播间隔 ≥200ms；真机验证 |
| RAM 紧张 | master 组件多 | 用 NimBLE、释放 Classic 内存 |
| 广播间隔与功耗 | 太短费电 | 默认 500ms，可业务调优 |
| 每台节点参数唯一 | 标错节点 | 参数化 + 配置表核对（验收实际扫描） |
| App 后台扫描限制 | 鸿蒙讲后台 | 逃生前台保活（文档已约定） |
