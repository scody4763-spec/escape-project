# 智能建筑消防逃生系统 - 项目文档

> 更新时间：2026-09-15
> 文档范围：`vue-go/` 当前代码与服务器部署状态

## 一、项目简介

本项目是一套面向多层建筑的 AIoT 消防逃生系统，覆盖：

- 环境与火灾数据采集
- 设备状态监测与告警
- BLE 信标定位
- 逃生路径规划
- 智能指示牌和吸顶灯控制
- Web 管理后台与 3D/2D 楼层可视化

当前建筑图数据包含 6 个楼层节点组，服务器数据库中的 `graph_node` 共有 71 条节点记录，并且均已配置 BLE `major/minor` 映射。

## 五、后端服务 (`aiot/aiot-v2/`)

```text

logic       业务逻辑
```

- JWT 保护路由：
  - `/api/users/*`

  - `/api/signboards/*`

### 5.3 管理员认证

- JWT Bearer Token
- bcrypt 密码哈希
- 支持管理员登录、登记、修改密码、用户列表和身份权限
- 实现位置：
  - `internal/middleware/auth.go`
  - `internal/logic/admin/admin.go`

### 5.4 MQTT 数据处理

主要订阅主题：

| 主题 | 用途 |
|------|------|
| `sensordata` | 环境传感器上报 |
| `signboard/heartbeat` | 指示灯心跳 |
| `ceiling_light/data` | 吸顶灯数据上报 |
| `indicator_light/data` | 指示灯数据上报 |

处理流程：

1. 按设备 MAC 解析 MQTT JSON。
2. 使用 Redis `SETEX` 更新在线状态。
3. 异步写入 InfluxDB。
4. 通过 WebSocket 推送给前端。
5. 检查火焰、电流和空气质量等告警条件。

### 5.5 实时推送

- 端点：`GET /api/ws/device-data`
- 实现位置：`internal/controller/ws/ws.go`、`internal/logic/ws/ws.go`
- 用途：将传感器和吸顶灯实时数据推送给 Web 前端。

### 5.6 告警与邮件

- 告警类型：
  - 设备离线
  - 火焰异常
  - 电流异常
  - 其他设备异常
- 告警状态：
  - `0` 未处理
  - `1` 已处理
  - `2` 已忽略
- 邮件通知：
  - SMTP over SSL
  - 实现位置：`internal/logic/email/email.go`
  - 发送记录写入 `notification_log`

### 5.7 指示牌和吸顶灯管理

指示牌和吸顶灯均支持管理端 CRUD。吸顶灯接口路径统一使用下划线：

```text
GET    /api/ceiling_lights
GET    /api/ceiling_lights/{id}
POST   /api/ceiling_lights
PUT    /api/ceiling_lights/{id}
DELETE /api/ceiling_lights/{id}
GET    /api/ceiling_lights/status
```

指示灯控制通过 `signboard/control` 发布 MQTT 指令，前端与后端路径已统一。

## 六、BLE 定位

### 6.1 接口契约

当前实际接口为：

```text
POST /api/location
```

请求：

```json
{
  "openid": "用户 OpenID",
  "beacons": [
    {
      "major": 3,
      "minor": 1,
      "rssi": -58
    }
  ]
}
```

响应：

```json
{
  "success": true,
  "floor": 3,
  "node_id": "f3-hall",
  "direction": "",
  "exit_name": "",
  "distance": 2.4,
  "estimated_time": 0
}
```

### 6.2 定位流程

1. 使用 `major/minor` 查询 `graph_node`。
2. 过滤未匹配节点的信标。
3. 使用 `RSSI + 100` 作为权重，计算 X/Z 加权质心。
4. 使用匹配节点数量最多的楼层作为定位楼层。
5. 选择距离质心最近的已知节点作为当前节点。
6. 无火灾时只返回定位结果。
7. 有火灾时使用 IACO 计算逃生路线，并返回出口、方向和预计时间。
8. 火灾联动时将方向指令下发给指示灯。

### 6.3 数据迁移

迁移文件：

```text
aiot/aiot-v2/manifest/deploy/sql/ble_major_minor_migration.sql
```

该迁移会为 `graph_node` 增加：

- `major`
- `minor`
- `idx_major_minor` 索引

服务器数据库已完成迁移，71 条节点均已有 `major/minor`。

## 七、逃生路径计算

### 7.1 后端接口

```text
POST /api/escape/calculate
```

主要请求字段：

| 字段 | 说明 |
|------|------|
| `algorithm` | `greedy`、`aco`、`iaco` 或 `compare` |
| `startNode` | 起点节点 |
| `floorId` | 楼层 |
| `fireMode` | 是否启用火灾模式 |
| `firePoints` | 起火节点列表 |
| `density` | 节点人员密度 |
| `safety` | 通道安全系数 |
| `compare` | 是否同时比较多种算法 |
| `params` | 算法参数覆盖项 |

后端处理流程：

1. 从 MySQL 加载 `graph_node` 和 `graph_edge`。
2. 火灾模式下移除电梯节点及其连接边。
3. 加载传感器节点绑定。
4. 调用 FastAPI 算法服务 `/api/escape/calculate`。
5. 返回多条路径、收敛数据和计算耗时。
6. 火灾演练模式下可向指示灯下发路径方向。

### 7.2 算法服务

服务地址：`http://127.0.0.1:8090`

接口：

| 方法 | 路径 | 说明 |
|------|------|------|
| `GET` | `/health` | 健康检查 |
| `POST` | `/api/escape/calculate` | 通用计算入口 |
| `POST` | `/api/escape/aco` | 基础 ACO 兼容接口 |

已实现算法：

- `greedy`：贪心路径，作为基线算法。
- `aco`：基础蚁群算法。
- `iaco`：改进蚁群算法，包含自适应挥发、精英更新、信息素上下限和多出口分配。
- `compare`：并行输出 Greedy、ACO 和 IACO 结果。

ACO 默认参数：

| 参数 | 默认值 |
|------|--------|
| 蚂蚁数量 | 30 |
| `alpha` | 1.0 |
| `beta` | 3.0 |
| `rho` | 0.3 |
| `Q` | 100 |
| 最大迭代次数 | 200 |
| 危险权重 | 10.0 |
| 密度权重 | 0.5 |
| 火灾影响半径 | 8 米 |
| 步行速度 | 1.5 米/秒 |

2. 跨楼层逃生路径仍需结合楼梯节点做进一步验证。

6. 通知日志页面尚未开放路由。
7. 生产环境建议启用 HTTPS、EMQX 账号认证、数据库备份和服务监控。
